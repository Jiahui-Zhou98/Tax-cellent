## Competitive Context

### Competitor: TaxSnapPro v1.8.16
- pip installable, Gemini 2.0 Flash, 8 forms, capital gains/NIIT/CTC/HSA/SALT/itemized
- **Zero NRA support.** No 1040-NR, no Form 843, no FICA exemption, no treaty logic.
- Target: domestic US filers. "Validated against CPA returns (0.05% difference)"

### Tax-cellent Moat (what TaxSnapPro cannot match)
- 1040-NR vs 1040 determination (NRA residency test)
- Form 843 FICA refund pre-fill
- F-1/J-1 FICA exemption (IRC §3121(b)(19))
- NRA standard deduction removal (correct for 1040-NR)
- State tax with NRA treatment
- Step-by-step explanation ledger (education over black-box)
- University-deployable (institutional hosting)
- Multi-provider LLM (not locked to Gemini)

## Vision

### 10x Check
Tax-cellent becomes the canonical NRA-native tax platform — the only product where
F-1/J-1/OPT students are first-class citizens and the rules are correct by default.
A student uploads W-2 + 1042-S + 1099-NEC, app determines NRA status, applies treaty
exemptions, generates Form 843 + 1040-NR draft, wraps in a printable filing package.
15 minutes. No CPA required. No TurboTax upsell. No "consult a professional" dead end.
Distribution: pip install taxcellent for end users — no Docker required for students or universities. Docker retained for developers.
Universities: white-label as the official international student tax resource.

"This was built by someone who actually files a 1040-NR."

Student from China, F-1 year 3, has W-2 + 1042-S fellowship + 1099-NEC from tutoring:

3. Upload 1099-NEC → SE tax calculated → NRA SE tax advisory shown
4. Combined: total refund = $3,847 (FICA refund + income tax refund)
5. Download: Form 843 (filled), 1040-NR (filled), filing cover sheet

### EUREKA
Everyone in the tax tool space serves the median American filer.
TaxSnapPro's 1099-DIV/B/capital gains features are irrelevant to most F-1 students.
Tax-cellent's moat is NOT breadth — it's vertical depth for the 1.1M international

## Accepted Scope

### Exp 1 — Form 1042-S
- OCR extraction: Box 2 (gross income), Box 3 (chapter indicator: 3=withholding, 4=FATCA),
  Box 4 (exemption code — determines income type: 15/16=scholarship/fellowship, 01=wages,
  20=business profit, etc.), Box 7a (federal tax withheld), Box 17a (state income)
- Box 4 exemption code → income category mapping (used by treaty logic in Exp 2):
  - 15, 16 → scholarship/fellowship
  - 01, 02 → wages/compensation
  - 06 → dividends; 07 → interest; 12 → royalties
  - Default (unrecognized code) → "other income" — no treaty exemption applied, show advisory flag
- New form type detection: "1042-S" in candidate_extractor
- `_calculate_1042s(gross, tax_withheld, user_context) -> list[CalculationStep]`
  - Calls `_apply_treaty_exemption(income_type, country, gross)` (Exp 2) → returns exempt_amount
  - taxable_1042s = max(0, gross - exempt_amount)
  - income_tax = _apply_brackets(taxable_1042s) if taxable_1042s > 0 else 0
  - balance = tax_withheld - income_tax
- `source_form="1042-S"` tag on all steps
- Add 1042-S card in CalculationLedgerStep (green accent — scholarship/fellowship)
- ContextStep: `has_1042s` checkbox already exists; use it to show 1042-S-specific guidance
- **Form 843 scope**: 1042-S does NOT trigger Form 843. Form 843 is for FICA overcollection
  on W-2 employment only. 1042-S withholding is income tax withholding (Chapter 3), not FICA.
- **NRA SE tax (1099-NEC)**: Already implemented (TODO-6). NRAs are exempt from SE tax under
  IRC §1402(b) by statute — not merely by treaty. The advisory flag language should be updated
  to: "As an NRA, you are generally exempt from SE tax under IRC §1402(b). SE tax has not been
  applied. Consult a tax professional if you believe you have US-source self-employment income
  that may be taxable." No new SE tax calculation changes needed for 1042-S.

### Exp 2 — Tax Treaty Country Selector
- Add `country_of_origin: Optional[str] = None` to UserContext (2-letter ISO: "CN", "IN", etc.)
- Add country dropdown to ContextStep (shown for non-domestic status)
- Data source: IRS Publication 901 (US Tax Treaties) — verify values before implementation
- Treaty table (hardcoded constants in tax_engine.py) — specific values per country:

| Country | Code | Income Type | Article | Annual Cap | Duration Limit |
|---------|------|-------------|---------|------------|----------------|
| China   | CN   | Scholarship  | Art. 20 | $5,000     | Unlimited       |
| China   | CN   | Wages (student) | Art. 21 | $5,000  | 3 yrs          |
| South Korea | KR | Scholarship | Art. 21 | $2,000  | 5 yrs          |
| Canada  | CA   | Scholarship  | Art. XXI | Unlimited | 5 yrs          |
| UK      | GB   | Scholarship  | Art. 20 | Unlimited | 5 yrs          |
| Germany | DE   | Scholarship  | Art. 20 | Unlimited | 4 yrs          |
| Japan   | JP   | Scholarship  | Art. 20 | Unlimited | 5 yrs          |
| India   | IN   | (none — no student scholarship exemption) | — | $0 | — |
| Brazil  | BR   | (no treaty with US) | — | $0 | — |
| Mexico  | MX   | Scholarship  | Art. 22 | Unlimited | 5 yrs          |
| Saudi Arabia | SA | (no treaty with US) | — | $0 | — |

- Note: Duration limit is years in current exempt-individual status. `first_us_entry_date`
  **already exists in UserContext** (added in TODO-6); `years_elapsed = 2025 - int(str(first_us_entry_date)[:4])`.
  No new UserContext field needed.
- **Non-scholarship/wage income types** (Box 4: 06=dividends, 07=interest, 12=royalties,
  unrecognized code): `_apply_treaty_exemption` returns `exempt_amount = 0.0` in v1, plus
  advisory flag: "Treaty exemption not applied for this income type — verify manually."
- **Multi-1042-S scenario**: Apply treaty logic to each 1042-S slot independently.
  Schedule OI shows one row per distinct (country, article, income_type). v1 limit: single
  active treaty country per filing (warn if two 1042-S forms have different `country_of_origin`).
- `_apply_treaty_exemption(income_type: str, country: str, gross: float, years_elapsed: int) -> float`
  - Returns exempt_amount (capped at min(cap, gross))
  - If no treaty, expired duration, or unrecognized income type → returns 0.0
- Treaty step in ledger: `source_form="TREATY"`, `is_flag=True`, cites treaty article + cap
- **UI disclaimer on treaty step**: "Treaty exemption applied per [Article] as sourced from
  IRS Publication 901. Verify treaty eligibility with your university's international student
  office before filing. Treaty benefits may require Form 8833 disclosure."
- **Call sequence in tax_engine.py**:
  ```
  calculate_combined(slots, user_context):
    for slot in included_slots:
      if slot.form_type == "1042-S":
        steps += _calculate_1042s(gross, withheld, user_context)
        # _calculate_1042s internally calls _apply_treaty_exemption
      elif slot.form_type == "W-2":
        steps += _calculate_w2(...)
      ...
  ```

### Exp 3 — 1040-NR PDF Generation
- Library: **`pypdf`** (choose this, not pdfrw — actively maintained, AcroForm fill via
  `PdfWriter.update_page_form_field_values`). Add to `pyproject.toml` dependencies.
- **Pre-implementation task (~1 day human effort)**: Extract AcroForm field IDs from
  official 2024 1040-NR PDF using pypdf. Document field-ID → line-number mapping before
  coding. IRS field names are not publicly documented and change yearly.
  ```python
  from pypdf import PdfReader
  r = PdfReader("f1040nr.pdf")  # download from irs.gov
  fields = r.get_fields()
  for name, obj in fields.items(): print(name, obj)
  ```
- Key line mappings (verify field IDs against actual PDF during pre-task):
  - Line 1b: wages (W-2 Box 1)
  - Line 8: other income (1099-NEC net)
  - Line 9: total income
  - Line 12: standard deduction (NRA: $0 — NRAs cannot claim standard deduction; show $0 explicitly)
  - Line 16: tax liability
  - Line 22: treaty-exempt income (from Exp 2; if > 0)
  - Line 25: federal income tax withheld (sum across all included docs)
  - Line 71: refund / amount owed
  - **Schedule OI** (required when Line 22 > 0): country of citizenship, treaty article,
    income type, exempt amount
- **XFA fallback**: If 2024 1040-NR PDF uses XFA forms (incompatible with pypdf AcroForm fill),
  use `reportlab` to render a flat overlay PDF instead. Budget 1 extra day if this path is hit.
- Download button in ReportStep alongside Form 843
- Warning banner: "Draft only — verify all values before filing. Tool is for estimation only."
- Annual update: `FORM_1040NR_YEAR = 2024` constant; update PDF template each January
- **Docker retained for development** — pip install is for end-user distribution; both supported

### Exp 4 — pip install Distribution
- `backend/setup.py` / `pyproject.toml`: add `[project.scripts] taxcellent = "taxcellent.cli:main"`
- CLI: starts uvicorn + serves pre-built static frontend
- **Frontend build strategy**: Check if the app uses Next.js App Router or Pages Router.
  - If Pages Router with no SSR: `next build && next export` → static files → works cleanly
  - If App Router or any SSR: use `output: 'standalone'` in `next.config.ts` + bundle Node
    runtime, OR convert dynamic routes to static. Verify before implementation.
  - CI: `next build` must run as part of `python -m build` (requires Node.js in build env)
  - Node.js is a **build-time dependency only** — users do not need Node installed
- Frontend static files embedded in Python package under `taxcellent/static/`
- FastAPI: `app.mount("/", StaticFiles(directory=static_dir, html=True))` after all API routes
- **Package size budget**: Target < 10MB sdist. Run `du -sh taxcellent/static/` after build.
  If > 10MB, split: serve static from CDN (GitHub Pages) with local fallback.
- **CI build order**: (1) `npm ci && npm run build` in `frontend/` → static output, (2) copy
  static files to `taxcellent/static/`, (3) `python -m build`. Node.js is required in CI env
  only; users need only Python. Pre-built static files are committed to the repo.
- Publish: `python -m build && twine upload dist/*` → PyPI as `taxcellent`
- README: update primary install instruction to `pip install taxcellent && taxcellent`
- Docker/Podman retained for development workflow — `docker compose up` still works

### Exp 5 — Include/Exclude Toggle
- `DocumentSlot`: add `included: bool = True`
- CalculationLedgerStep: per-slot checkbox "Include this document" (default checked)
- On toggle: re-POST to `POST /api/analyze/combined` (new endpoint) with body
  `{ document_ids: string[], included_mask: boolean[] }`. `calculate_combined()` filters
  to included slots and returns a fresh `TaxReport`.
- `calculate_combined()`: filter `[s for s in slots if s.included]`
- Min-doc guard: if all slots unchecked, show "Include at least one document"

### Exp 6 — Accuracy Validation Badge
- `backend/tests/accuracy_scenarios/`: 10-15 JSON fixtures (NRA scenarios with known outcomes)
  - nra_f1_w2_only.json, nra_f1_w2_1042s_china.json, nra_f1_nec_only.json, etc.
  - Each fixture: input fields + expected_tax, expected_refund, expected_form_type
  - Sourced from: anonymized real returns, hand-calculated scenarios, or CPA-reviewed cases
- `backend/tests/test_accuracy.py`: run tax_engine against each fixture, compute MAE
- **CI gate scoped to NRA accuracy scenarios only** — not general tests. Threshold: MAE < 5%
  (conservative; 2% was too strict before treaty logic is stable). Gate documented in CI config.
- N is dynamic: `len(os.listdir("accuracy_scenarios/"))` at test time. Frontend displays
  the count read from a `backend/app/accuracy_report.json` generated at test time.
- `accuracy_report.json` is generated by `test_accuracy.py` during CI and **committed to the
  repo** under `backend/app/accuracy_report.json`. It is bundled into `taxcellent/static/` at
  build time. Frontend reads it at startup via the FastAPI static file serve.
- Frontend landing / report header: "Validated against N NRA filing scenarios"
- **Multi-provider LLM already implemented** (Ollama, OpenAI, Anthropic, Gemini) — no new work.
  It's listed as a moat but is already shipped. Not in scope for this plan.
